
## Before you open a pull request

**Open an issue first**, tagged `design discussion` or `bug`. We will review it,
discuss where needed, and give an explicit go. Pull requests come after the go.

This is not bureaucracy. The question "is this the right shape for the fleet?"
costs ten lines in an issue and costs a working implementation plus two review
rounds after a PR exists — and a reviewer looking at finished code is under
quiet pressure to find a way to take it. We would rather spend your effort on
changes we have already agreed we want.

Bug fixes with an obvious shape move fast: report, reproduce, fix, release.
Most issues get a go quickly; the gate is cheap because of that.
